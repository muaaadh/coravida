# Coravida — how this repository works

A Maldives private-charter site (one vessel, **Tiffany Blanc 14**) and the office's admin,
in four languages. Vanilla HTML/CSS/JS generated by a Node script; no framework, no
client-side build. Live at **https://coravida.vercel.app/**, admin at `/admin/`.

## The rules that matter

1. **Never edit a generated file.** `*.html`, `ru/ zh/ de/`, `excursions/*.html`,
   `assets/js/data*.js`, `content/media.json`, `sitemap.xml` are all output. Edit
   `content/site.json` (the data) or `tools/build.js` (the markup), then build.
2. **Deploy only with `bash tools/deploy.sh "message"`.** It pulls with rebase, builds,
   pushes `content/site.json` into the database, commits, pushes (Vercel deploys on push to
   `main`) and mirrors the built site into the client's OneDrive folder. A plain `git push`
   skips the content step and the next build then rebuilds from the *database*, silently
   discarding the repo edit — or failing if it names a picture that no longer exists.
3. **Content lives in the database, not in the repo.** The Vercel build overwrites
   `content/site.json` from the `content.site` row before building, because the office edits
   it through the admin. `tools/content-up.sh` is what keeps the repo's copy authoritative
   when a developer changes it.
4. **Every visible string goes through `T("…")`** and must be translated in
   `tools/i18n/{ru,zh,de}.js`. `node tools/build.js` prints anything untranslated and, for
   content, warns when a positional list has drifted. Array overrides match by
   `slug` / `id` / `img` / `file` / `src` — never by position if the item has one of those.
5. **Secrets stay in `.env.local`** (gitignored): `SUPABASE_SERVICE_KEY`,
   `SUPABASE_DB_PASSWORD`, `ADMIN_FIRST_PASSWORD`. The *publishable* key in
   `assets/js/env.js` is meant to be public — row-level security decides what it may do —
   and that file is rewritten at build time from `SUPABASE_URL` / `SUPABASE_ANON_KEY`.
6. **Check the result in a browser, not by reading the diff.** There is a headless harness
   (below); layout, film and the calendar have all broken in ways that only a screenshot
   showed.

## Build and run

```bash
node tools/build.js                  # every page, data*.js, media.json, sitemap
node tools/vercel-build.js           # what Vercel runs: DB content → build → _site/
bash tools/deploy.sh "message"       # the only way to ship
bash tools/content-up.sh             # push content/site.json into the database
bash tools/export.sh handover/data   # take the whole database out
bash tools/import.sh handover/data   # fill a fresh database (schema first)
```

Media (agency machine only — the sources live in OneDrive):

```bash
bash tools/film.sh [name …]          # every clip, source resolution, seamless loops, posters
bash tools/film.sh --raw             # the drone clips, stream-copied, no re-encode
bash tools/film.sh --posters         # posters only
bash tools/enhance.sh [name …]       # the drone clips' 2160/1440 tiers via Real-ESRGAN (~1 h)
bash tools/images.sh                 # photograph tiers from the shoot
bash tools/tiers.js                  # tiers for photographs uploaded through the admin
```

## Where things are

```
content/site.json        all content: brand, rates, voyages, add-ons, arrange, gallery, faq, hero, music
tools/build.js           the generator: T(), TP(), deepMerge, img()/tier(), every page function
tools/i18n/{ru,zh,de}.js one file per language: ui (keyed by the English string), chrome, content
assets/js/site.js        the browser: header/menu/footer, the sea, hero cycle, film, player, gcal, enquiry
assets/css/site.css      one stylesheet
admin/                   db.js (the only file that touches Supabase) · app.js · content.js · books.js
                         calendar.js · inbox.js (the enquiries board) · history.js · admin.css
api/publish.js           Vercel function: verifies a staff JWT, fires the deploy hook
supabase/schema.sql      tables, RLS, grants, triggers, realtime, the uploads bucket
handover/HANDOVER.md     moving the site to another Vercel + Supabase account
```

## Things that have bitten before

- `--dsp` is the display-font variable, **not** `--display`; a rule using the wrong one
  silently falls back to the body font.
- The glass calendar's hidden `date`/`alt` inputs live inside its mount — `innerHTML = ""`
  wipes the form. `gcal()` only removes non-input children.
- A hero clip shorter than `hero.interval` used to wrap and show its own start again. Clips
  are now stretched past the hold, and the player hands over at a short clip's end.
- The drone footage is only the DJI app's **1080p proxies**; its 1080 tier is stream-copied
  (`data-raw`, no loop dissolve — the page hands over or dips instead), and 2160/1440 are
  machine-enlarged. Real 4K originals would replace both scripts.
- `/opt/ImageMagick/bin/convert` fails with "bad CPU type"; use ffmpeg + `cwebp`.
- `ffmpeg` inside a `while read` loop eats the loop's stdin — always `-nostdin`.
- The books' sync depends on the exact `updated` stamps: only what *this* device changed is
  sent (a dirty set in the cache), a folded row is never sent back, and the database drops
  any copy that is not newer (`keep_newer`). Do not "simplify" that.
- OneDrive dehydrates files mid-session and `rsync` dies on it; the mirror uses `tar`.

## The headless harness

The scratchpad is wiped between sessions; rebuild it when it is gone.

```bash
node serve.mjs ~/coravida 8899            # static server with range requests (for video)
bash chrome.sh                             # Playwright chrome-headless-shell on :9222
node cdp.mjs <url> <script.js> <w> <h> [out.png]   # DPR=2 for a Retina check
```

`script.js` runs in the page as an async function; its return value is printed and console
errors are reported. Google Chrome is not installed; Python's `http.server` hangs the
newer engines.

## Admin facts

Sign in at `/admin/` with the staff e-mail and password; sign-ups are closed, accounts are
made in Supabase. Content edits are a draft in `localStorage` until **Publish**, which
writes `content.site` and fires the deploy hook. The books keep one row per record in
`records`; enquiries land in `inbox` and appear on the board (New → Contacted → Quoted →
Booked → Lost). History is the log, never deleted.
